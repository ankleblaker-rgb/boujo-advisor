# 出荷・売上管理 — GitHub Pages / Firebase 版

不二・豊島・千住の出荷箱数と概算単価をまとめて入力し、月別・年別に集計します。

## 公開・ログイン

- このフォルダを既存の `boujo-advisor` リポジトリへ追加します。
- GitHub Pages の公開先は既存設定を利用します。
- 防除アドバイザーと同じ Firebase プロジェクト `farm-ai-system`、同じ Google アカウントを使用します。
- 出荷記録は `shipping_accounts/{uid}` の専用文書に保存します。防除の文書は更新しません。
- Firebase の Web 設定値は公開アプリの設定です。権限は Firebase Authentication と Firestore ルールで制御します。
- 本版は運用者1アカウント用です。UID の制限をクライアントと Firestore ルールの両方で行います。

## 初回に必要な Firebase 設定

1. Firestore の既存ルールを控えてから、`firestore-rules-addition.txt` の match 節を既存の `/databases/{database}/documents` の内側に追加します。日誌・防除の既存ルールは残します。
2. Firebase Authentication の Google ログインと承認済みドメインに `ankleblaker-rgb.github.io` があることを確認します（防除で利用済みの構成）。
3. 新ページで Google ログインし、保存後「共有保存済み」になること、別端末に同じ記録が出ることを確認します。

## ChatGPT 版からの記録移行

1. 旧ページを開き、「共有保存・バックアップ」→「バックアップを保存」で JSON をダウンロードします。
2. 新ページを開き、防除と同じ Google アカウントでログインします。
3. 「共有保存・バックアップ」→「バックアップから復元」で、その JSON を選択します。
4. 復元は新ページのスマホ・PC共通の全記録の置き換えです。確認画面の件数を確認してください。旧ページのデータは削除しません。
5. 共有保存済みを確認してから、別端末で同じ Google アカウントを使って開き、件数・箱数・売上を確認します。
6. 移行と共有の確認が終わったら、新ページをスマホのホーム画面に追加します。

端末内保存だけの旧版を利用していた場合は、旧版のバックアップでも同じ手順で移行できます。

## 保存時の動作

- Firestore トランザクションと版番号で古い内容による全記録上書きを防ぎます。
- 同じ記録の変更が競合した場合は入力を残して保存を停止します。必要な入力を控え、共有内容を読み直して修正し直してください。
- 接続失敗時は入力を残します。共有保存済みになるまでは画面を閉じないでください。本版にオフライン送信待ちの機能はありません。
- 共有保存データには容量確認があります。上限に近い場合は上書きせず、バックアップを保存するよう案内します。
- 既存のバックアップ形式（`farm-shipping-sales`, version 1）を継続利用します。

## 検証

`shipping` フォルダで `npm test` を実行します。追加パッケージのインストールは不要です。

テスト対象：3市場の保存と再取得、概算集計、古い版からの上書き拒否、修正と削除、日付・重複・形式検証。

Firebase の実環境での Google ログイン・ルール適用・スマホ/PC間の同期確認は、接続と設定を完了してから行ってください。
